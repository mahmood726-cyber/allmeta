# Validate the extras in R

This panel checks the separate intercept-only three-level REML extras: CR2 coefficient inference using study clusters, Satterthwaite degrees of freedom and 95% confidence intervals, and 95% profile-likelihood intervals and plotted coordinates for both variance components. The pinned replay checks the current numerical implementation, displayed cells, labels, exported JSON, and plot geometry and painted styles against a clean render in the same browser. It does not resist CSS deliberately injected into the page. It is not an assessment of whether a pooled effect is scientifically meaningful for a particular dataset.

The original estimator and its 528-check contract are separate. `#alm-plus` contains all extras, and the original page's autosave is installed with selectors that exclude `#alm-plus`, so the extras cannot write into the original app's stored state or shift its positional keys; a regression test pins the original key set. The original adapter's rendering check is confined to `#summary`; its explicit `#alm-plus` exclusion (the only change to an existing validate file) preserves that scope and the 528-check count. The panel follows the `limit-ma` and `proportion-ma` plus pattern (`plus-adapter.js`, `MANIFEST-plus.json`, `plus-pins.js`, `README-plus.md`) and uses the shared `AlmValidate.mount` interface without changing shared code. Its two buttons are renamed so that they do not share accessible names with the original panel.

## Corpus and methods

`dataset-disposition-plus.csv` and `plus-corpus/inventory-plus.json` retain a decision and reason for all 114 datasets in metadat 1.6-0. They come from the paper's local reproducibility archive, `data/dataset-disposition.csv`. Forty-one datasets supply 44 configurations, including four configurations from dat.lim2014. All original finite-row inputs are retained; exclusions and omitted source rows are recorded in each reference's source metadata. There are no exclusions based on the JavaScript comparison result. Diagonal sampling covariance and an intercept-only reduction are used consistently; overlapping endpoints, phylogeny, spatial structure and temporal sampling covariances are not reconstructed.

Those 44 configurations all have at least four clusters, so a second pinned corpus covers the few-cluster regime: `plus-corpus/regime-corpus-plus.json`, 21 synthetic configurations with two or three clusters plus one 21-row six-cluster design generated with both variance components at zero. They are the few-cluster designs of the independent review of this feature, reproduced by `regime-corpus-plus.R` from its seed, and they matter for three reasons: CR2 there has one or two Satterthwaite degrees of freedom; it is the regime in which `confint.rma.mv`'s own upper search bound actually truncates a profile limit (see below); and the double-boundary design puts both components on the zero boundary, where `rma.mv` stops at 2.7e-13 and 4.4e-13 while the browser engine returns exactly zero with a restricted log-likelihood 6e-11 higher, equal to the value `optim`/Nelder-Mead reaches. Each sampling variance is stored as the exact square of its double standard error, so the browser replay — which types standard errors into the page and squares them again — reads bit-identical variances rather than values one double rounding apart. That rounding is also why this corpus does not reproduce the review's observation that `nlminb` refuses that design outright: on the review's unrounded copy of the same design `rma.mv` reports `convergence = 1`, and on this copy, whose variances differ by at most 4.4e-15, it converges. The refusal turns on the last digits of the sampling variances, so it is reported here as a fragility of the optimiser rather than claimed as a property of the design; the generators keep an optimiser fallback for it, which this corpus does not trigger. These configurations are synthetic, not published data, and are labelled as such.

Native references use R 4.6.0, metafor 5.2-1, metadat 1.6-0, clubSandwich 0.7.0 and jsonlite 2.0.0. Profile references use `metafor::profile.rma.mv` (nine marks including zero) and `confint.rma.mv`, with the other component re-estimated. Initial `rma.mv` fits use REML and nlminb `rel.tol=1e-10`; Maire uses BFGS `reltol=1e-14`. Confidence-limit root tolerance is `1e-8`, maximum 1,000 iterations. Failed profile roots are retried with Nelder–Mead `reltol=1e-12`, maximum 10,000 iterations; the configuration's control and warnings are retained.

`confint.rma.mv` searches a variance component in `[0, vc.max]` with `vc.max = max(10, 100*estimate)` and, when the likelihood-ratio cutoff is not crossed inside that interval, returns that bound itself as the limit. It reports this only through `ub.sign` (`">"`) in the returned object: there is no warning, no message and no printed output, so `$random[1,]` alone cannot be told apart from a genuine profile root, and reading it without the sign pins a truncated search bound as a reference. `profile-limit-plus.R` therefore passes `vc.max` explicitly and widens it tenfold until `ub.sign` is empty, i.e. until the limit is interior to the searched interval; `pin-plus.mjs` refuses to pin any limit that equals the default bound, and `compare-plus.mjs` reports how many pinned limits are interior. This bound truncates no limit in the 44 metadat configurations (0 of 88) but three of the 42 regime limits, all in two-cluster designs. Those cases are recorded in `plus-corpus/divergences-plus.json` with metafor's default-bound value, the widened value, and the profile restricted log-likelihood of each minus the target `ll_max - qchisq(0.95,1)/2`, all computed by metafor: the widened limit sits on the cutoff and the default-bound value sits above it, so the search stopped before reaching the limit. That file is pinned evidence, not a replay input.

Both sides bound the search, and neither reports a bound as if it were a limit. The browser engine brackets upwards from `max(2*estimate, scale)` with at most 60 doublings, and `fit` takes an optional `searchBound` — the analogue of metafor's `vc.max`. A limit the search does not reach is reported as unavailable: `null` in the result and the export, and the text `not estimable (> upper search bound)` in the table, never a number. The nine marks then end at 1.5 times the estimate, which is also what the reference grid does, so both sides evaluate the same abscissae either way. With the default bound the restricted likelihood of this model falls to minus infinity as a component grows — there are always at least two clusters — so no admissible input reaches it; the behaviour is exercised in the tests through an explicit narrow `searchBound`.

For the p-value tolerance, the native R script refines the variance estimates with the analytic REML score, using a numerical score Jacobian and at most 40 Newton iterations. Scores are scaled by `max(mean(v),var(y),1e-12)`; the stopping target is `1e-11` and the final score check is `1e-7`. `clubSandwich::coef_test(vcov='CR2', test='Satterthwaite')` and `conf_int` then operate on an `rma.mv` object conditional on these R-refined variance estimates. The exact conditioning values are stored in `cr2Sigma2`; they are not JavaScript output. This step avoids making the tight p-value check depend on small differences between optimiser stopping points. It does not imply that one implementation is more accurate than R.

The browser engine independently profiles the two-component restricted likelihood using analytic scores: a logarithmic bracketing grid, up to 70 bisections per score root, a scale-relative `1e-13` interval target, and explicit zero boundaries. Profile confidence limits use up to 75 bisections and `1e-11` scale-relative interval width. CR2 uses the symmetric adjustment formed from the Cholesky factor of the fitted marginal covariance and an inverse square root; cyclic Jacobi eigendecomposition allows at most 100 sweeps. Student t probabilities use a continued fraction with `2e-15` convergence, and critical values use 90 bisections.

In the few-cluster regime the two sides agree less closely on the variance estimates themselves than on the metadat corpus: the largest deviation over all 65 configurations is 7.2e-7 on a within-study variance estimate (`rv043_Bfew`), against the 1e-6 tolerance. That is R's optimiser stopping point rather than engine error, and the direction is checked rather than asserted: the restricted log-likelihood at the engine's estimates is higher than R's in 18 of the 21 regime configurations, equal in two, and lower in one by 1.8e-15. Both the numerical script and the engine test report that the engine's restricted log-likelihood is never below R's by more than `1e-12` relative to `max(1,abs(R))`, and fail if it is. Over all 65 configurations the largest shortfall is 2.6e-12 on a log-likelihood of 442.66 (`dat.mccurdy2020`), 5.8e-15 relative — floating-point noise in a sum over a hundred rows, three orders of magnitude below the 1e-9 differences that a genuinely worse optimum produces.

Closed-form CR2 calculations conditional on the R variance estimates are checked at `1e-9` relative to `max(1,abs(R))`. Fitted quantities and profile values are checked at `1e-6` on that scale. All p-values use `1e-9` absolute error. Counts, quantity labels and refusal text are exact. The numerical script makes 59 checks per configuration over both corpora, 3,835 total, and separately reports that 130 of 130 pinned profile limits are interior to their search interval. Browser replay has 165 checks per configuration plus 24 checks for eight refusals, 10,749 total. The refusals include the four radix and non-finite row forms (`0x1F`, `0b101`, `0o17`, `Infinity`): `Number()` accepts radix literals, so the row parser matches decimal and exponent forms before converting. These are expected counts; see the run reports for actual outcomes.

Plot checks compare effective screen coordinates (within 0.05 CSS pixels), computed paint, opacity and text with a clean same-browser SVG render. Scale marks must first match R. The clean render uses those validated marks so decimal rounding at a tick boundary cannot make a correct display fail. Axis labels are checked because the scale is determined by the validated marks. The nine-point line is a sampled profile, not a continuous optimisation trace.

## Live and offline tiers

Live webR uses the existing same-origin webR 0.5.5 / metafor 4.8-0 bundle to check the current profile coordinates, variance estimates, confidence limits and log-likelihood. It does not claim a live clubSandwich check: that package is absent from the pinned webR repository. The full offline replay checks CR2 against the native R references. An unavailable live package or failed R optimisation must be reported as a refusal or failure, never as a pass.

`MANIFEST-plus.json` describes the corpus. `plus-pins.js` independently holds its SHA-256 values for all seven files. New JSON corpus files are pinned on UTF-8 LF bytes; the two regime files are written with `digits = 22`, which round-trips every double exactly, because jsonlite's `digits = NA` keeps only 15 significant digits. The shared widget verifies the bytes before parsing and caches them for subsequent offline replays; on `file:` URLs it offers file selection. No third-party network request is needed for validation. The corpus generation script refuses to pin an incomplete or unrefined reference set.

## Reproduce

From `multilevel-ma/`, with R 4.6.0 and the packages above installed, run:

```powershell
# Optional: an additional existing library holding clubSandwich, appended after the default libraries.
$env:ALM_EXISTING_R_LIB='<path to a library containing clubSandwich>'
Rscript validate/generate-plus.R
Rscript validate/refine-reference-plus.R
Copy-Item validate/plus-corpus/refined-reference-plus.json validate/plus-corpus/reference-plus.json
Rscript validate/regime-corpus-plus.R      # few-cluster regime inputs, from their seed
Rscript validate/generate-regimes-plus.R   # their references and divergences-plus.json
node validate/pin-plus.mjs
node validate/compare-plus.mjs
```

The generator resumes completed configurations. To regenerate from scratch, rename the generated reference file before running it. Every R script prints `.libPaths()` and package versions. No package was installed for the pinned references; clubSandwich 0.7.0 came from an existing library appended after the prescribed ones.

Browser and engine tests are ordinary Playwright tests in `hub/shared/tests/multilevel-ma-plus.spec.mjs` (run from `hub/shared/tests` with `npx playwright test multilevel-ma-plus.spec.mjs --workers=1`). They cover the 3,835 engine checks in Node, the original 528-check replay, the 10,749-check extras replay, the clean table and plots at 1280 px and 375 px, a planted negative for every numerical, displayed and exported quantity, the display/export schema, the geometry, paint and axis-label checks of each plot, all refusals, stale-input invalidation, keyboard use and changed reference bytes. They also cover the three parts of the search-bound contract — no pinned limit is metafor's default bound, the recorded divergences adjudicate in favour of the widened limit, and an unreached limit is displayed and exported as not estimable — together with the radix-literal refusals and a regression test asserting that the saved autosave key set of the original app is unchanged by the extras. The live webR test is tagged `@slow`. Setting `ALM_PLUS_EVIDENCE=1` writes the replay and live results to `validate/plus-evidence/`.
