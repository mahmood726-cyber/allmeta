# Screen workflow upgrade

This is a focused upgrade of the existing AllMeta Screen, reviewed against official product documentation on 18 October 2026. It is not a feature-parity claim or a head-to-head usability study. The live deployment inspected at the start was the GitHub Pages `/allmeta/screen/index.html` app; changes in this branch require merge and deployment before appearing there.

## Comparison and priorities

| Area | Current comparison evidence | AllMeta change / remaining gap |
|---|---|---|
| Ranking | [ASReview stable model documentation](https://asreview.readthedocs.io/en/stable/lab/models.html), headed 3.0.8, lists ELAS u4 (TF-IDF/bigrams + SVM), custom query strategies, and optional semantic/multilingual Dory models. | Retains the existing local TF-IDF/Naive Bayes implementation. Adds reviewer/stage isolation, stale-state handling, uncertainty ordering, optional batch retraining and recorded training labels/configuration. No SVM, embeddings, multilingual performance claim or new accuracy superiority claim. |
| Everyday screening | [Rayyan Workbench](https://www.rayyan.ai/workbench) documents facets, blinded collaboration, automatic removal of decided records, sampling and keyboard shortcuts. | Fixes the active-reviewer undecided queue and advances without skipping a newly visible successor. Existing hotkeys/focus mode retained; adds explicit stage controls and undo. Saved sampling sets and workload assignment remain missing. |
| Title/abstract and full text | [Rayyan full-text setup](https://help.rayyan.ai/hc/en-us/articles/45704446101393-How-to-Set-Up-Full-Text-Screening-in-Rayyan) describes distinct decisions, manual PDF attachment and plan-dependent retrieval/matching. | Adds separate full-text decisions, OA URL/evidence notes, retrieval states and required exclusion reasons. Only title/abstract consensus includes are eligible. No embedded PDF reader, PDF storage, OCR, annotation or automatic retrieval. |
| Independent reviewers | Rayyan documents hiding peer decisions and unblinding to reconcile. | Both reviewers must decide before consensus is final; blind UI and ranking use the active reviewer only. Local reviewer slots are not authenticated accounts. Anyone with the backup/browser storage can inspect both reviewers. |
| Adjudication | Rayyan documents conflict resolution as a team workflow. | Named adjudicator plus rationale, recorded history, and invalidation when underlying decisions change. There is no server-enforced third-reviewer role. |
| Import/export | ASReview supports dataset/project exports; Rayyan supports reference import/export and PDF management. | Retains RIS/NBIB/CSV/JSON; fixes quoted multiline CSV and malformed JSON handling; adds complete project restoration, stage-specific reviewer exchange and richer CSV. Full project JSON is the lossless backup; CSV/RIS are exchange reports, not lossless project restores. BibTeX and `.asreview` interoperability are not implemented. |
| Audit/reproducibility | [ASReview project management](https://asreview.readthedocs.io/en/stable/lab/manage.html) documents archiving data, history and model configuration. | Adds dated action history and ranking snapshots to JSON backups. Imported legacy decisions have no invented timestamps/history. History is local and unsigned, not a tamper-proof record or authenticated audit. |
| Reporting | Separate screening stages must not confuse pending work with exclusions. | PRISMA export refuses pending reviews and distinguishes full-text non-retrieval/exclusions. Extract receives final full-text includes from v2 projects. Counts describe reports; study-level reconciliation remains manual. |
| Accessibility/performance | No comparative accessibility or throughput measurements were made against either competitor. | Native labelled controls, keyboard-operable actions, live status, mobile layout checks, one-card rendering and regression checks. No WCAG conformance certification or 100k-record latency claim. |

ASReview comparison is documentation-based. Its flexible learning and simulation platform is substantially broader than this browser ranker. Rayyan's hosted team administration, document management and ResearchPilot capabilities are not replicated here. The valuable differentiator remains a local, inspectable workflow without requiring an account.

## Decision contract

`screen-v1` remains the storage envelope for existing integrations, with `workflowVersion: 2`. Existing `r1`, `r2` and `resolved` fields remain title/abstract decisions. `fullText` holds independent reviewer slots, adjudication, retrieval state, OA URL and notes. A full-text decision never rewrites its title/abstract decision.

In dual mode: duplicate → excluded from review; explicit adjudication → final; two matching decisions → agreement; two differing decisions → conflict; one missing decision → pending. `maybe` is not a final eligibility decision. Changing a reviewer decision clears that stage's adjudication. Final include exports require a retrieved full text and a final full-text include.

Reviewer files retain `sr-reviewer-v1` for the shared-folder adapter, adding an explicit `stage`. Files without a stage are legacy title/abstract files. Differing existing decisions and conflicting identifiers are refused instead of silently overwritten. Use a shared backup to establish record identity, agree reviewer slots out of band, and deliberately clear a decision before importing a revised version. Full-text exchange uses manual file export/merge; folder publishing is title/abstract only.

Blind mode is a presentation and ranking safeguard, not an access-control boundary. Complete backups intentionally contain both reviewers and history. Team summaries/CSV/final includes require unblinding. Protocol terms, record metadata and full-text evidence are shared project material.

Open full-text screening after completing title/abstract decisions and unblinding; then enable blind mode again for independent full-text decisions. On small screens the screening card precedes project settings. Recent ranking scores remain available, explicitly marked as needing retraining, after a decision; switching reviewer, mode or stage clears them. Optional retraining runs after ten new decisions on the main thread; this is not a background-worker implementation. Browser storage capacity remains a limit, so export backups regularly. A quota failure stays visibly marked as unsaved; unreadable stored data is preserved and downloadable rather than silently replaced.

The previous UI turned a rank-sorted sequence into a “confidence of recall” and “safe to stop” claim. That presentation is removed. The existing mathematical `mlBuscarP` hook remains for its oracle tests; it is not used to advise stopping. Cross-validation AUC on reviewer-selected labels does not establish recall in the unscreened pool.

## Static versus dynamic disclosure

| Item | Origin | Limitation |
|---|---|---|
| Workflow enums, stage names, 10-decision retraining interval | Static software settings | Workflow defaults, not research findings |
| Decisions, counts, history, model label snapshots | User imports and recorded actions | No invented decisions or reconstructed legacy history |
| Ranking scores | Existing deterministic local model trained on current labels | Uncalibrated ordering, no recall/accuracy guarantee |
| Cold-start RCT classifier | Existing trained weights and metadata | Unchanged in this upgrade; not an eligibility classifier |
| Synthetic fixtures and built-in demo | Explicitly labelled teaching/test material | No DOI/PMID/NCT/study dates asserted as real; no research findings |
| Existing labelled-corpus test | Committed Cohen Triptans fixture | Regression check, not a fresh ASReview/Rayyan head-to-head benchmark |

## Validation commands

From the repository root:

```text
python -m pytest screen/tests -q -p no:cacheprovider
node --test screen/tests/workflow.test.cjs
```

From `tests/playwright`:

```text
npm ci
node node_modules/@playwright/test/cli.js test --config screen-workflow.config.mjs
```

The focused browser configuration binds only to `127.0.0.1:8000`, uses installed Chrome locally and bundled Chromium in CI. It runs the complete Screen browser suite and targeted Extract integration checks. The portfolio-wide app suite and an Overmind release verdict are separate gates; this document does not assert either passed.

Local validation on 18 October 2026: 80 browser tests passed (including the existing real-corpus ranking regression), 36 Screen Python tests passed, and 8 workflow unit tests passed. Asset lint, offline citation grounding, claim/code drift sweep, UTF-8/BOM checks and `git diff --check` passed. Sentinel exited successfully with no BLOCK findings; its existing document-language warnings and accessibility INFO findings are not a WCAG audit.

The synthetic 2,500-record load/filter/render check took 171 ms on the final local run, against an 8-second regression threshold; it rendered one record card. This is a bounded fixture measurement on one machine, not a maximum dataset size or comparative performance claim. Desktop and mobile full-text layouts were visually inspected. A focused GitHub Actions workflow repeats the screening checks on Linux/Chromium; remote CI results belong to the PR checks, not this local evidence record.
