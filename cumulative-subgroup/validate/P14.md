# P14 year-block conclusiveness

Open **Year-block conclusiveness (P14 rule)** below the existing app, paste a JSON
array, select FE/DL/REML and Wald/HK, and choose **Evaluate P14**. The existing
CSV input, PM views, exports and live/corpus validation continue to operate
independently. The P14 panel is not covered by the existing PM validation button.

Each input row contains numeric yi, exactly one of positive sei or vi, an integer
report year from 1 through 9999, optional nonnegative integer n, and optional label.
Missing n is retained as unknown. RR/OR/HR must already be on the log scale.
MD/SMD remain on their analysis scale. The null is zero; intervals are 95%.

The output includes every distinct year, including unevaluated k<2 blocks.
j_star is a one-based index into that full table. A qualifying start must precede
the final year block. Sensitivity (a) applies k>=10 to the starting block only.
Known null inclusion or the opposite direction defeats a candidate suffix.
If no suffix passes, a suffix containing only the final direction and UNDEFINED
would pass if its undefined statuses resolved in that direction: the result is
INDETERMINATE. This includes an undefined candidate start. Earlier undefined
blocks do not invalidate a later fully observed qualifying suffix. A final
UNDEFINED is always INDETERMINATE; a final INCLUDES is NOT_CONCLUSIVE.

N_later and N_lag2 are null with their incomplete flag true if any counted row
lacks n. Empty counted sets have k=0, n=0 and incomplete=false. Summary fields
without a qualifying crossing are null. T is an ISO date representing 31 December
of the crossing year. CSV repeats both summaries and settings on every block row;
JSON additionally includes canonicalized input rows. Input changes clear stale
results and disable exports until the analysis is run again.

FE has no estimated heterogeneity, so its exported tau2 is null. FE uses Wald
only. DL and REML re-estimate tau2 at every evaluated year. HK uses k-1 degrees
of freedom and no variance floor. A finite zero-SE HK interval is classified
normally. Exceptions and non-finite fits are UNDEFINED, not discarded rows.

## Reference generation and checks

From the repository root, with Rscript, metafor, jsonlite, Python/pytest, Node,
the existing hub/shared/tests npm dependencies and a Playwright browser installed:

    Rscript --vanilla cumulative-subgroup/validate/p14-reference.R cumulative-subgroup/tests/fixtures/p14-fixtures.json cumulative-subgroup/validate/p14-reference.json
    python -m pytest -q -p no:cacheprovider cumulative-subgroup/tests

The new browser test serves the repository on 127.0.0.1:8000. That port must be
free. PW_CHANNEL may select an installed browser, as in the existing harness.

Also run all existing cumulative-subgroup Playwright specs from hub/shared/tests:

    npx playwright test cumulative-subgroup --project=chromium --reporter=line

Those pre-existing specs use their existing server configuration on port 8088.
No validation corpus, manifest, adapter, or shared statistics file is modified.

The R generator writes the reference; do not author its JSON manually. It records
R.version.string, installed metafor/jsonlite versions, solver controls, and MD5
checksums binding the local fixture/generator bytes (freshness checks, not
cryptographic authenticity). Unexpected fit errors abort generation. The REML
fault fixture uses maxiter=0 and must actually produce a convergence error.
The JS harness injects the corresponding exception only at that fixture's
specified cumulative subset size; production offers no fault-injection option.

REML references use threshold=1e-13, maxiter=10000 and stepadj=0.5 so stopping
error does not mask the 1e-9 estimate/SE/bound comparisons. Tau2 tolerance is
1e-6 absolute. Other numeric tolerances are 1e-9*(1+abs(reference)); all rule,
membership-count and completeness outputs match exactly. Reverse-order inputs
must produce byte-identical JSON after canonical sorting.

The exact-zero boundary is tested directly in both independent classification
functions. It is not claimed that an independently rounded R and JS FE fit will
both construct a bit-exact zero bound. Synthetic zero-residual HK fixtures
separately prevent an incorrect zero-SE refusal.

| Item | Static definition / hardcoding | Dynamic evidence |
|---|---|---|
| Rule | Null=0, 95% CI, k>=2, sensitivity k>=10, lag=2 years | Every year block and both decisions from input rows |
| Fixtures | Explicit synthetic numerical inputs, expected categorical edge cases | All fitted numbers generated by installed metafor |
| Computation | Existing shared estimators; exact normal 97.5% quantile | Refit on each cumulative subset, no fitted values embedded in app |
| Provenance | P14 schema version | App version from AlmBuildInfo; R/package versions from running generator |
| Failure test | Declared forced-convergence fixture | R must fail; Node exercises the production exception handling |
