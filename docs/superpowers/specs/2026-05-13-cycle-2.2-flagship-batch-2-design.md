4. **No engine math changes.** Adapter shims map to the existing engine.

## 3. Per-anchor specifics

### heterogeneity

- CSV columns: `study, yi, vi` (same as forest-plot).
- R-parity: `rma.uni(yi, vi, method="REML")` → compare `tau2, I2, Q, QEp, k, ci.lb, ci.ub`.

### pet-peese

- CSV columns: `study, yi, sei` (SE direct, not variance).
- R-parity: PET = `regtest(rma.uni(yi, sei=sei), model="lm", predictor="sei")` → compare `slope, slope_se, zval, pval`. PEESE = same but `predictor="vi"` (where `vi = sei^2`).

### effect-size-converter

- Multiple input modes (means+SDs → SMD; events+totals → logOR / logRR; etc.). Skip CSV upload for the v0.1 retrofit — the app's input shape is mode-dependent. Wire url-state + results-export + tooltips at minimum. Mark axis-controls "n/a" (no plot).
- R-parity: a 1-row fixture per major conversion (means→SMD via `metafor::escalc(measure="SMD")`; events→logOR via `escalc(measure="OR")`). Test 2-3 conversions.

### dta-sroc

- CSV columns: `study, TP, FP, FN, TN`.
- R-parity: `mada::reitsma` → compare `mu1, mu2, tau2_alpha, tau2_theta, rho`. **Bivariate convergence can fail for k<5**; use a 6-row fixture.

### nma-pro-v2

- **User-flagged: verify-first.** Run the feature-presence audit FIRST. If audit shows `chart-download = present-good` (likely — earlier grep showed the app has a 19,844-line nested asset with `FileReader`), skip migration. Be conservative.
- CSV columns: `study, treat1, treat2, yi, sei` (long format) OR `study, treatments, effects, ses` (wide). Adapt per existing schema.
- R-parity: `netmeta::netmeta(TE=yi, seTE=sei, treat1, treat2, studlab=study)` → compare `TE.random, seTE.random` for one comparison.
