## 1. Goal & non-goals

**Goal.** Build a Playwright-based runtime auditor that probes all 66 in-repo allmeta apps and produces `runtime-health.{json,csv,md,html}` at the repo root. Each app is classified into one of five states using L2 depth (load + primary-mount + console-error check + UI text scan for service-unavailable). Output is committed and the dashboard is hub-quality.

**Why this is needed.** The triage atlas (Cycle 1) measures filesystem signals — it cannot see runtime failures. `rct-extractor` reports "API not reachable" in the UI but passes every atlas signal (has tests, has README, hub-linked, fresh git). The user surfaced this manually. The audit makes this class of defect first-class.

**Non-goals.**

- **No fixes** in this cycle. The audit produces evidence; Cycle 3.2 designs the remediation.
- **No L3 interaction scripts** — page-loads + primary-mount-initialised is the depth.
- **No extension of the triage atlas rubric in this cycle.** The signal exists in `runtime-health.json` for a future atlas cycle to consume. Hub UI stays unchanged.
- **No remote / external apps** — Al-Mizan, AdaptSim, CardioOracle, etc. are hosted elsewhere; this audit covers in-repo apps only (the same scope as the triage atlas).
- **No changes to individual app code.** Read-only.
- **No new external dependencies.** Playwright is already installed in `hub/shared/tests/`.

## 2. Architecture

### Folder layout (additive, separate from `triage/`)

```
allmeta/
├── audit/
│   ├── runtime_health.py     CLI entry-point + orchestrator
│   ├── probe.spec.mjs        Playwright spec — parameterised per app
│   ├── classifier.py         probe result → state + reasons
│   ├── render.py             emits json/csv/md/html
│   ├── tests/
│   │   ├── test_classifier.py
│   │   └── fixtures/
│   └── README.md
├── runtime-health.json       data contract (atlas v0.2 may consume)
├── runtime-health.csv
├── runtime-health.md
└── runtime-health.html
```

Separate from `triage/` because the runtime model differs. Triage = filesystem scan, runs in seconds, re-run often. Audit = real browser load, runs in minutes, re-run rarely. Keeping them in separate folders means `python triage/scan.py` doesn't accidentally trigger the slow browser audit.

### Components

1. **App-list source** — re-uses `triage/projects_js.py` (Cycle 1) to read `hub/projects.js`. Filter to in-repo apps (`path` starts with `./`). External URL apps are skipped.
2. **Playwright probe** (`audit/probe.spec.mjs`) — parameterised via `process.env.ALM_AUDIT_APPS_JSON` (list of `{key, path}` records). Loads each app, captures the four observations: `load_ok`, `console_errors[]`, `mount_found`, `ui_text_matches[]`. Writes raw results to `audit/.probe-output.json`.
3. **Classifier** (`audit/classifier.py`) — pure function: `(raw_probe_result) → {state, reasons[], confidence}`. Five states (Section 3).
4. **Renderer** (`audit/render.py`) — same shape as `triage/render.py` (which Cycle 1 already shipped). Emits the four artifacts at the repo root.
5. **CLI orchestrator** (`audit/runtime_health.py`) — `python audit/runtime_health.py [--workers 4] [--timeout 30]`. Reuses the local HTTP server pattern from Cycle 2.1 (`python -m http.server 8088 --directory <repo-root>`), spawns Playwright with the apps list, parses the raw output, classifies, renders.

### Data flow

```
hub/projects.js
     │
     ▼
projects_js.load_projects()  →  [{key, path}, ...]
     │
     ▼
probe.spec.mjs (Playwright, workers=4, timeout=30s/app)
     │
     ▼
.probe-output.json  →  classifier.py  →  records[]  →  render.py
                                                           │
                                                           ▼
                                       runtime-health.{json,csv,md,html}
```

### Parallelism

4 Playwright workers. 66 apps ÷ 4 ≈ 17 batches × ~10s = **~3 min wall time** on a warm cache. Local HTTP server reused via `reuseExistingServer: true`.

## 3. Classifier (6 states, first-match-wins)

### Probe observations per app

```json
{
  "key": "forest-plot",
  "url": "http://localhost:8088/forest-plot/",
  "load_ok": true,
  "load_time_ms": 642,
  "timed_out": false,
  "console_errors": ["..."],
  "mount_found": true,
  "ui_text_matches": []
}
```

### State rules (top-down, first match wins)

```
UNKNOWN
    probe_crashed == true
    (Playwright itself errored; we have no observations for this app.
     Distinct from TIMEOUT, which means the probe ran fine but the page
     stalled.)

TIMEOUT
    timed_out == true
    (page didn't reach networkidle within 30s; nothing else observable)

NEEDS-SERVICE
    load_ok == true AND ui_text_matches.length > 0
    (must fire BEFORE CONSOLE-ERRORS, because an unreachable-backend app
     legitimately console.errors on its fetch — that's the symptom, not a
     real defect to fix.)

CONSOLE-ERRORS
    load_ok == true AND filtered console_errors.length > 0

MISSING-MOUNT
    load_ok == true AND console_errors.length == 0 AND mount_found == false
    (page renders but no primary interactive landmark — hello-world page,
     stub, or broken init)

OK
    everything else
```

### Mount-landmark detection (Playwright selector)

A page has a "primary mount" if **any** of these is visible after `networkidle`:

```javascript
const MOUNT_SELECTOR = [
  'svg',                                       // forest, funnel, bubble, prisma flows
  'canvas',
  'textarea',                                  // paste-based data input
  'table input',                               // data-entry tables
  'button:has-text(/compute|run|pool|estimate|analy[sz]e|extract|score|update|render/i)',
].join(', ');

const mount_found = await page.locator(MOUNT_SELECTOR).first().isVisible({ timeout: 2000 });
```

Heuristic. False negatives (a working app with none of these) are possible — any MISSING-MOUNT result is flagged for human-eyeball review rather than auto-killing.

### NEEDS-SERVICE patterns (regex, case-insensitive, applied to `document.body.innerText`)

```javascript
const NEEDS_SERVICE_PATTERNS = [
  /\bnot reachable\b/i,
  /connection (refused|failed)/i,
  /\bcannot connect\b/i,
  /server (down|unavailable)/i,
  /\bunavailable\b/i,
  /ollama not (running|reachable)/i,
  /start the .* server/i,
];
```

The probe records which patterns matched in `ui_text_matches[]` so the report shows why. Aggressive matching is OK — a false positive surfaces an app whose help text mentions a server requirement, which is useful information.

### Console-error filter (drop the noise)

Drop messages matching these — they're noise, not real defects:

```javascript
const BENIGN_ERROR_PATTERNS = [
  /Content Security Policy/i,
  /favicon\.ico/i,
  /Failed to load resource.*(?:127\.0\.0\.1|localhost):/i,
];
```

### Confidence

- `high` — all 4 observation channels reported cleanly
- `medium` — `mount_found` heuristic returned `false` but page otherwise clean (could be false-negative; needs human review)
- `low` — TIMEOUT or UNKNOWN (we don't actually know what's wrong)

### Reasons array

Each record carries `reasons[]` like the triage atlas — humans see the *why* of every classification.

## 4. Outputs, error handling, v0.2 hooks, scope

### Outputs (mirror Cycle 1 triage atlas)

| Artifact | Purpose |
|---|---|
| `runtime-health.json` | data contract (atlas v0.2 may consume) — schema versioned, `audit_version` stamp |
| `runtime-health.csv` | flat one-row-per-app; sortable |
| `runtime-health.md` | committed, grouped by state (UNKNOWN → TIMEOUT → NEEDS-SERVICE → CONSOLE-ERRORS → MISSING-MOUNT → OK), each app: name · top reasons |
| `runtime-health.html` | single-file filterable dashboard; same aesthetic as `triage.html`; state filter chips + search + sortable table |

### Error handling

| Condition | Behavior |
|---|---|
| Single app probe crashes Playwright | record `state = UNKNOWN`, audit continues |
| HTTP server doesn't start | fail closed with explicit error; no partial artifacts written |
| Playwright not installed | fail closed; suggest install command |
| App folder listed in `projects.js` but missing on disk | skip with WARN (same as `triage/scan.py`) |
| App returns HTTP 404 | record `load_ok=false`; classifier maps to `MISSING-MOUNT` with reason "HTTP 404" |

### Acceptance criteria

1. `audit/` folder exists with the 5 source files + tests.
2. Classifier has ≥10 unit tests covering each state boundary + the noise-filter cases.
3. `python audit/runtime_health.py` runs end-to-end in <5 min on the 66 in-repo apps.
4. Four committed artifacts exist at the repo root.
5. The runtime-health dashboard renders correctly when opened in a browser; filter chips work.
6. The known-broken `rct-extractor` lands in `NEEDS-SERVICE` (sanity check on the headline classification).
7. The 3 Cycle-2.1 anchors (forest-plot, funnel-plot, meta-regression) all land in `OK`.

### v0.2+ hooks (signposted, NOT built in this cycle)

- **Triage atlas v0.2 signal.** Extend the atlas rubric to read `runtime-health.json` and demote apps in non-OK states to Tier 4 or 5. The atlas already supports overrides — `runtime_health: needs-service` becomes a new Tier-4 reason.
- **L3 interaction sequences.** Per-app scripts that paste demo data → wait → check for output. Substantial scripting work — defer.
- **Backend probe.** For `NEEDS-SERVICE` apps, also probe the declared backend URL (`/health` endpoint) and report whether the backend is reachable separately from "app reports backend unavailable". Helps Cycle 3.2 design "graceful degradation" properly.
- **Nightly CI.** Add to Overmind's nightly verifier — flags new regressions as code lands.

### Scope guardrails / non-goals

- No fixes. Pure audit.
- No changes to any app's source.
- No new dependencies — reuse `@playwright/test` from `hub/shared/tests/node_modules/` (Cycle 2.1).
- One PR. Branch `feat/cycle-3.1-runtime-audit` off `main`.

### Branch & PR shape

- Single branch `feat/cycle-3.1-runtime-audit`.
- Commit chain: scaffold → classifier with tests → probe → renderer → orchestrator → first real run + commit artifacts → tag `cycle-3.1-v0.1.0`.
