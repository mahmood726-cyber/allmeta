## 1. Goal & non-goals

**Goal.** Build 7 reusable JS modules in `hub/shared/` covering the user-flagged UX gaps:

1. CSV upload + format docs
2. Multi-format chart download (PNG/SVG/PDF) with no edge-crop
3. Axis controls (X/Y range, log toggle, tick density)
4. Results export (JSON/CSV/Markdown)
5. URL state / deep-linking
6. Reset / clear-all / undo
7. Inline help / glossary tooltips

Retrofit three anchor apps — `forest-plot`, `funnel-plot`, `meta-regression` — end-to-end so each meets all 9 dimensions of flagship quality: 7 UX dims via shared modules + ≥3 tests + 1 R-parity test against metafor. After this cycle, all three apps should be promotable to **Tier 1** by the triage atlas (built in Cycle 1) — that is the success criterion.

**Non-goals.**

- The other 5 flagships (heterogeneity, dta-sroc, nma-pro-v2, pet-peese, effect-size-converter) — Cycle 2.2.
- Non-flagship apps (60+ remaining) — opportunistic, not in this cycle.
- Changing any anchor's math/engine. Hardening is UX + tests + parity, not a rewrite.
- New external CDN dependencies. One vendored dep (jspdf, MIT, ~150 KB) committed in `hub/shared/vendor/`.
- No build step (no webpack, no rollup, no minifier). Plain `<script>` includes.
- No hub-level changes. `hub/app.js`, `hub/styles.css`, `hub/projects.js`, `index.html` all untouched.
- **Don't regress any app that already has working UX features.** Some flagship and non-flagship apps already implement custom CSV upload, chart download, or other dimensions — often better-tuned than a generic shared module would be. User-flagged "in good shape, verify before changing" so far: **Pairwise Pro** (`Pairwiseai/e156-submission/assets/pairwise-pro-v2_2_evalue (5).html`, 19,844 lines, has `FileReader` + custom upload UI) and **nma-pro-v2** (per user; not yet audited). The §4 feature-presence precondition is a hard gate, not a checklist suggestion — if an existing implementation is working, keep it.

## 2. Architecture & module API

### Folder layout (additive, all new)

```
hub/shared/
├── csv-upload.js          ~200 LOC
├── chart-download.js      ~250 LOC
├── axis-controls.js       ~150 LOC
├── results-export.js      ~150 LOC
├── url-state.js           ~100 LOC
├── reset-undo.js          ~120 LOC
├── tooltips.js            ~120 LOC
├── glossary.json          ≥80 terms (HKSJ, REML, tau², SMD, etc.)
├── vendor/
│   └── jspdf.min.js       vendored, MIT, ~150 KB
└── tests/
    ├── _r_parity.py       shared R-parity helper (reused by anchors)
    └── test_*.py / *.spec.mjs  per-module unit tests
```

### Namespace

Each module attaches one property to `window.alm` (allmeta). Plain JS, no ES modules, no build step. Apps include via `<script src="../hub/shared/csv-upload.js"></script>` before their own inline script.

### Uniform API contract

Each `window.alm.<module>` is a **callable that also carries methods**. Calling it initialises (idempotent). After init, the same `window.alm.<module>` exposes module-specific methods for the app to invoke imperatively (e.g. `alm.resetUndo.snapshot()`).

```js
// Init (idempotent — second call on same target replaces)
window.alm.csvUpload({
  target: '#mount-point-id',         // selector or element
  ...module-specific opts...,
  onChange: (state) => { ... }       // app's re-render hook
});

// Post-init imperative methods (per module)
window.alm.resetUndo.snapshot();     // for example
window.alm.urlState.write(state);    // for example
```

Four rules every module follows:

1. **Idempotent init.** Calling twice on the same target replaces, never duplicates.
2. **Self-contained styles.** Each module injects a `<style>` block at first init. No external CSS file to keep in sync.
3. **Zero inter-module deps.** Apps include only the modules they need; no implicit dependency graph.
4. **Callable-with-methods.** `typeof window.alm.<module> === "function"`; module-specific methods hang off it.

### Module responsibilities (one sentence each)

| Module | Responsibility |
|---|---|
| `csv-upload` | File picker + drag-drop + paste + auto-detect delimiter + expandable "Expected format" panel + RFC-4180 parser → emits `{headers, rows, warnings}` |
| `chart-download` | Three buttons (PNG/SVG/PDF). Edge-crop fix: union bbox + 12px viewBox padding before serialise. PNG via HiDPI canvas. PDF via vendored jspdf |
| `axis-controls` | Min/max inputs per axis + log toggle + tick-density slider; emits change events |
| `results-export` | Three buttons (JSON/CSV/Markdown) on a `getResults()` callback |
| `url-state` | `read()` and `write(obj)` against URL hash. Base64+JSON, 4 KB cap, warning toast if exceeded |
| `reset-undo` | Snapshot/restore callbacks + undo button + "Clear all" with confirm; stack capacity default 20 |
| `tooltips` | Scans for `<abbr data-gloss="HKSJ">` markers; attaches accessible CSS+ARIA tooltips reading from `glossary.json` |

## 3. Per-module behavior (non-obvious bits)

### 1. csv-upload

- **Column mapping.** If a CSV column name doesn't match the expected `name` in `columns[]`, a one-line mapping UI surfaces ("Map *evt* → ?"). Fuzzy auto-match via Levenshtein ≤2.
- **"Expected format" panel.** Inline table: column name · type · required · example value, plus a **Download sample CSV** button that emits a valid CSV the app will accept. Closes the loop on "where do I start?".
- **Parser.** RFC-4180 in ~50 LOC (quotes, embedded commas, embedded newlines, trim). No external dep.
- **Warnings array.** Emitted alongside parsed rows (e.g. "row 14 dropped: n_event > n_total"). Not errors — app decides whether to halt or skip.

### 2. chart-download — edge-crop is the headline fix

- **Padding before serialise.** Walks every visible SVG element, computes the union bbox via `getBBox()`, expands `viewBox` by 12px each side. Labels and tick text never clip again. This is the single defect flagged most concretely by the user.
- **Inline external CSS.** If SVG references styles from external stylesheets (very common — chart styles live in app's `index.html`), the downloaded SVG would render unstyled. Module walks computed styles on each SVG node and inlines them as `style="..."` attributes. ~30 LOC.
- **PNG path.** Serialised SVG → data URL → off-screen `<img>` → `canvas` at `2 × devicePixelRatio` → `toBlob()` → download. Anti-aliased, retina-sharp.
- **PDF path.** `jspdf.svg()` plugin (vendored). Page size auto-fits chart bounds + 12px padding. Single-page.

### 3. axis-controls

- **Validation.** Min < max enforced inline; log toggle disables if any data ≤ 0; reset-to-auto restores data-driven range.
- **Library-agnostic.** Module knows nothing about Plotly/Chart.js/raw-SVG. Emits `{x: [min,max], y: [min,max], xLog, yLog, ticks}` to a callback; app re-renders.

### 4. results-export

- **CSV formula-injection guard** (per `lessons.md`): cells starting with `=`, `+`, `@`, `\t`, `\r` get a `'` prefix.
- **Markdown.** Pipe-escaped, fixed-width-padded. Pastes cleanly into manuscript drafts or GitHub issues.
- **Numbers en-US locale.** Avoids "1.234,5" Excel reimport trap.

### 5. url-state

- **Version stamp.** State object has a `v: 1` field at top. On read, mismatched majors return `null` (app starts fresh). Same fail-open pattern as `triage.json`'s `scanner_version`.
- **4 KB cap.** Exceeded → warning toast "URL too long for this dataset; use Save Project file instead." No silent truncate.

### 6. reset-undo

- **Snapshot timing.** Snapshot is taken **before** each user-initiated mutation, not on every observable change. Apps call `alm.resetUndo.snapshot()` in their mutation handlers. Stack capacity default 20; oldest dropped on overflow.
- **Confirm dialog.** Uses `<dialog>` element (well-supported since 2022); `Escape` cancels. No `window.confirm()` fallback needed.

### 7. tooltips

- **Accessibility.** Tooltip has `role="tooltip"` and stable id; triggering `<abbr>` gets `aria-describedby` pointing to it. Visible on hover **and** keyboard focus.
- **Touch.** One-tap reveals; tap-elsewhere dismisses. No long-press requirement.
- **Glossary canonical.** `glossary.json` is single source of truth — courses/, workflow/, individual apps all read the same file. ≥80 terms (HKSJ, REML, DL, PM, Sidik-Jonkman, I², τ², PI, SMD, OR, RR, HR, RD, NMA, SUCRA, POTH, GRADE, CINeMA, ROB-2, ROBINS-I, QUADAS-2, AMSTAR-2, PRISMA, …).

## 4. Per-anchor retrofit plan

### Feature-presence precondition (applies to every anchor — hard gate, not a suggestion)

Before wiring any module into an anchor, grep the app for existing implementations. Don't blindly stamp over working code. This rule applies equally to Cycle 2.2 (and is the reason Pairwise Pro / nma-pro-v2 are user-flagged for verify-first treatment).

| Dim | grep marker heuristic |
|---|---|
| CSV upload | `type="file"`, `accept=".csv"`, `FileReader` |
| Chart download | `toBlob`, `toDataURL`, `application/pdf`, `download=`, `svg` serialise |
| Axis controls | `<input` near "min" / "max" / "log" near plot |
| Results export | `application/json`, `text/csv`, `Blob` near "result" |
| URL state | `location.hash`, `URLSearchParams`, `pushState` |
| Reset/undo | `<button[^>]*reset`, undo, history stack |
| Tooltips | `<abbr`, `title=`, `data-gloss` |

Three outcomes per dimension per app:

1. **Absent.** Wire in the shared module.
2. **Present and good.** **Keep as-is.** Do not migrate. The shared module may even be inferior to a hand-tuned implementation. Record "skipped, existing implementation kept" in the retrofit commit message.
3. **Present but broken/partial.** Replace with the shared module. Record the specific defect being fixed in the commit message.

For the anchors specifically (forest-plot, funnel-plot, meta-regression), each retrofit task BEGINS with a feature-presence audit and explicitly lists which of the 7 dimensions fall into each of the three outcomes. No assumption-based retrofits.

### Generic integration pattern (applies to all three anchors)

1. Add 7 `<script src="../hub/shared/<module>.js">` tags at the bottom of `<head>` (before the app's inline `<script>`).
2. Add 7 mount-point divs in the app's markup at natural locations (data-input area, chart toolbar, settings panel).
3. Wire up via `alm.<module>(...)` calls in the existing app `<script>`, replacing custom input/download/help code that already exists.
4. Annotate method labels with `<abbr data-gloss="HKSJ">HKSJ</abbr>` markers.
5. Run existing test + 2 new tests + R-parity test (4 tests total per anchor).
6. Manual browser gate (see §5).

### forest-plot

- **Existing:** study table input (custom textarea); forest plot SVG; pooled effect.
- **Retrofit pinch points:** textarea → `alm.csvUpload` (columns: `study, yi, vi` *or* `study, n1, m1, sd1, n2, m2, sd2`); attach `alm.chartDownload` to forest plot SVG; `alm.axisControls` for effect-axis range; `alm.resultsExport` for pooled-estimate table; `alm.urlState` for dataset + method choice; `alm.resetUndo` around the study table; `alm.tooltips` for DL/REML/PM/HKSJ labels.
- **R-parity test:** `tests/test_against_metafor.py` — fixture CSV → R `rma.uni(yi, vi, method="REML")` → compare `b, se, ci.lb, ci.ub, tau2, I2, Q, QEp, k` at `atol=1e-6`.

### funnel-plot

- **Existing:** study table → funnel plot + Egger's regression test.
- **Retrofit pinch points:** same module set. Axis controls especially relevant — funnel y-axis is log-SE, so log toggle + y-min/max are exactly the flagged defect. CSV columns: `study, yi, sei`.
- **R-parity test:** `tests/test_against_metafor.py` — `regtest(rma.uni(...))` (Egger). Compare `zval, pval, slope, slope_se`.

### meta-regression

- **Existing:** study table + covariate columns → bubble plot + permutation test.
- **Retrofit pinch points:** same modules. Column-mapping UI matters most here because covariate names are user-defined. CSV: `study, yi, vi, <covariate_1>, <covariate_2>, …`.
- **R-parity test:** `tests/test_against_metafor.py` — `rma.uni(yi, vi, mods = ~ x)`. Compare `b[0:2], se[0:2], pval[0:2], R², QM, QMp`.

## 5. Testing strategy + R-parity harness

### Test layout per anchor

```
<anchor>/
├── tests/
│   ├── test_<anchor>.py              (existing — keep)
│   ├── test_csv_upload.py            (new — module integration smoke)
│   ├── test_export.py                (new — JSON/CSV/Markdown roundtrip)
│   └── test_against_metafor.py       (new — R-parity)
```

Target: **4 tests per anchor**, **12 across the three**. Plus per-module unit tests in `hub/shared/tests/`.

### Shared R-parity harness — write once, reuse across all 3 anchors

`hub/shared/tests/_r_parity.py`:

```python
def assert_r_parity(allmeta_result, *, r_call, fixture_csv, tol=1e-6):
    """Run R via Rscript on fixture_csv with r_call template, parse
    JSON output, compare every numeric field of allmeta_result against
    R within tol. Skip with clear marker if Rscript unavailable."""
```

- **Rscript path:** `C:\Program Files\R\R-4.5.2\bin\Rscript.exe`.
- **Skip-on-missing-R:** if Rscript isn't on the runner, tests **SKIP** with `pytest.skip("Rscript not available — R-parity check requires R 4.5.x")`. Skip is not pass; the triage atlas's R-parity signal counts "test file present" but a fresh run on a real R install is the gate before tier-promotion.
- **Tolerance:** `atol=1e-6` for deterministic estimators (per `advanced-stats.md`). Stochastic methods (permutation tests) get `atol=0.05` and 3-sigma bounds.

### What each anchor's R-parity test compares

| Anchor | R function | Compared fields |
|---|---|---|
| forest-plot | `metafor::rma.uni(yi, vi, method="REML")` | `b, se, ci.lb, ci.ub, tau2, I2, Q, QEp, k` |
| funnel-plot | `metafor::regtest(rma.uni(...))` | `zval, pval, slope, slope_se` |
| meta-regression | `metafor::rma.uni(yi, vi, mods=~x)` | `b[0:2], se[0:2], pval[0:2], R2, QM, QMp` |

### Per-module unit tests in `hub/shared/tests/`

- **csv-upload:** RFC-4180 parser cases (embedded commas, quotes, newlines); column fuzzy-match maps `evt → n_event` within Levenshtein 2.
- **chart-download:** viewBox is expanded by 12px before serialise; PNG output is a valid PNG signature; no `</script>` substring in serialised SVG.
- **axis-controls:** emits change event with expected shape; log toggle disables when data ≤ 0.
- **results-export:** CSV cells starting with `=` are prefixed with `'`; Markdown table is pipe-escaped.
- **url-state:** 5 KB state → "too large" warning, not silent truncate; version mismatch → null on read.
- **reset-undo:** snapshot/restore round-trip; stack cap drops oldest.
- **tooltips:** `aria-describedby` wired to a stable id; missing glossary entry falls back to textContent.

Target: **~25 module unit tests + 12 anchor tests = ~37 new tests** in this cycle.

### Manual browser-test gate

Per `CLAUDE.md` / `rules.md` ("For UI or frontend changes, start the dev server and use the feature in a browser before reporting the task as complete"), every retrofit task ends with a local-server check:

- Open anchor in browser → upload sample CSV → render chart → download PDF → confirm no edge-crop → use undo → share URL → reload from URL → confirm restored state.

That manual gate is the failure mode the atlas's automated signals can't catch.

## 6. Error handling, v0.2 hooks, scope guardrails

### Module error handling (uniform)

| Condition | Behavior |
|---|---|
| Module's target element doesn't exist | `console.warn` + no-op. No throw. |
| `window.alm.<module>` not loaded but called | Thrown `TypeError` (developer bug, not user error). |
| CSV parse errors | Emit `warnings[]` array; never throw. |
| Chart-download SVG missing | Button hides itself; no error. |
| `url-state` write exceeds 4 KB | Toast warning; no silent truncate. |
| `url-state` read version mismatch | Return `null`; app starts with defaults. |
| `reset-undo` undo with empty stack | Button disabled; no error. |
| `tooltips` glossary entry missing | Falls back to the `<abbr>`'s textContent. |

### Cycle 2.1 acceptance criteria

1. All 7 modules exist in `hub/shared/` with self-contained styles + idempotent init + ≥2 unit tests each.
2. `hub/shared/vendor/jspdf.min.js` committed (vendored, MIT-licensed).
3. `hub/shared/glossary.json` committed with ≥80 terms.
4. forest-plot, funnel-plot, meta-regression each:
   - Begin with a feature-presence audit (the three-outcome rubric from §4); audit results recorded in the retrofit commit body.
   - Include the relevant module scripts ONLY for dimensions that fell into outcome "absent" or "present-but-broken/partial".
   - Have 4 tests (existing + 2 new + 1 R-parity).
   - Pass the manual browser gate.
5. **Do-no-harm gate.** Manual browser sanity must confirm that every UX feature present BEFORE the retrofit is still present AFTER (specifically: anything from outcome "present and good" must still work). A "before/after" smoke-test note in the retrofit commit body records what was verified.
6. Re-running `python triage/scan.py` shows all three anchors at **Tier 1** (rubric reads `test_count >= 3 AND has_r_parity AND fresh AND is_hub_linked` — all satisfied post-retrofit).
7. Hub's featured strip auto-populates with the three anchors (Tier-1 detection in `hub/app.js`).
