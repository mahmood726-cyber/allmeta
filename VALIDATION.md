# allmeta — Validation & Verification Dossier

**Consolidated 2026-06-07.** This document assembles the *existing, CI-gated* validation
evidence for the allmeta evidence-synthesis stack into one place. It is a consolidation of
artifacts that already live in three repositories — not a new validation run. Every figure
below is reproducible from a committed script; the reproduction command is given in each
section.

Scope: this dossier covers **numerical correctness** (S4 synthesis) and **robustness /
provenance** (S5 verify-falsify-sign). It does **not** claim validation of the screening,
search, or extraction stages (S1–S3), nor of the judgement-scaffold instruments (INSPECT-SR,
ROB-ME), which are faithful implementations of published instruments, not numerically
oracle-checked. See *Boundaries* at the end.

## 1. Synthesis correctness — R/Stata parity (S4)

Source: `allmeta/parity/parity-ledger.js` (auto-generated by
`scripts/build-parity-ledger.mjs`), gate `tests/test_parity_coverage.py`.

| Metric | Value (ledger generated 2026-06-06) |
|---|---|
| Browser-app parity specs | **44** |
| Python-engine parity tests | **19** |
| Total parity tests | **63** |
| Assertions (JS) | **173** |
| Assertions (Python) | **77** |
| Distinct R oracles | **41** |
| Stata cross-anchors | **38** |
| Tolerance | **1e-6** (1e-8 for UWLS, 1e-9 for multiplicative-NMA) |

Oracles: `metafor`, `meta`, `netmeta`, `dmetar`, `dosresmeta`, `EValue`, plus closed-form and
`lm()` checks. This is **stronger provenance than CMA or RevMan**, neither of which ships a
public test suite, and is at parity with `metafor` (which serves as the oracle, not a
competitor — allmeta is checked *against* it).

**Honest uncovered disclosure (6 apps, no packaged R oracle — disclosed in the ledger,
enforced by `test_parity_coverage.py`):** `everything-model`, `cross-network`, `cross-design`,
`sequential-ma`, `bma-tau-priors`, `nma-dose-response-app`. These are bespoke or
research-grade estimators with no standard R equivalent; each is formula- or
analytically-checked and the ledger states the reason. The coverage test fails closed if any
of these silently acquires a parity test without being removed from the uncovered list.

Reproduce: `node scripts/build-parity-ledger.mjs && python -m pytest tests/test_parity_coverage.py`

## 2. Robustness falsification at corpus scale — spec-collapse (S5)

Source: `spec-collapse-atlas` (repo), gate `ci/check_against_metafor.py`.

Across **473 Cochrane intervention meta-analyses** (Pairwise70 corpus, k ≥ 3), a 36-spec
specification grid run through the calibrated weighted-likelihood t-mixture aggregator:

| | Naive IV-RE pool | Corrected (weighted-likelihood) |
|---|---|---|
| Conclusions called "robust" | **88%** (417/473) | **33%** (157/473) |
| **False robustness** (IV-RE robust → corrected fragile) | **260/473 = 55.0%** | |

The 55% reversal is **stable at 52–55%** across uniform, REML-only, and HKSJ-only weighting
schemes. The aggregator is externally validated against `metafor`/`metadat` in CI.

Reproduce: `python run_corpus_full.py` (full 473-review atlas + sensitivity);
`python ci/check_against_metafor.py` (parity gate).

## 3. Signed end-to-end provenance — Evidence Integrity Observatory (S5)

Source: `evidence-observatory/out/pilot_full_bundle.json` (HMAC-signed bundle),
tests `evidence-observatory/tests` (7/7, incl. signature-tamper detection).

| Field | Value |
|---|---|
| Reviews loaded | **473** |
| Skipped (honest exclusion from denominator) | **122** |
| Errored | **0** |
| Headline false-robustness | **54.97%** (260 false-robust / 417 IV-RE-robust) |
| Specification-fragility | **66.81%** |
| Signer | `overmind.verification.signers.select_signer` (HMAC; key from env/gitignored file, never the bundle) |
| Signature | `6e57faef…0950fb` (publish gated on `verify()` round-trip) |

**Why 54.97% here vs 55.0% in §2 (documented, not a discrepancy):** the observatory loader
recomputes each pool as **FE-Wald** from the `.rda` study data, while the §2 atlas uses the
published **36-spec random-effects grid**. Same corpus, two legitimate recompute conventions;
**neither is the Cochrane-published RE number** (which would require RevMan-exact REML +
HKSJ-floor + Q-profile per the repro checklist). The two figures agreeing to within 0.03 pp is
itself a cross-method consistency signal.

Reproduce: run the observatory pipeline under `evidence-observatory/observatory`, then
`python -m pytest evidence-observatory/tests`.

## 4. Comparative axis — what this catches that the field does not

The S5 layer exists to catch a failure mode the dominant front-end tools do not check.
Published, independent evidence (not a head-to-head re-run by us):

| Tool / study | Task | Reported accuracy |
|---|---|---|
| **Elicit** (self-reported) | "extraction" across 994 Cochrane reviews | 96% — **but** ground-truth = *Characteristics-of-included-studies* tables, i.e. descriptive/categorical fields, **not** numerical effect tuples |
| Yun et al. 2024 (independent) | continuous-outcome extraction, best LLM (GPT-4) | **48.7% exact match** |
| Sallam et al. 2025 (independent) | GPT-4o / o3 overall extraction | 72.6% / 75.3% |
| Tan & D'Souza 2026 (independent) | full meta-analytic association *tuples* | **near-zero** (role reversals, binding drift, numeric misattribution) |
| SR literature (general) | per-paper extraction error | **8–63%** |

The "right number bound to the wrong arm/outcome/timepoint" failure (Tan & D'Souza) is
precisely what the signed grounding + fragility + parity layer is designed to surface before a
number reaches synthesis. **Positioning: allmeta is the verification gate that starts where
AI-extraction reliability ends — not a screening competitor.**

## 5. Boundaries — what this dossier does NOT claim

- **Parity ≠ inferential correctness.** Numerical agreement with R proves the implementation
  matches the reference algorithm; it does not validate that the chosen method is appropriate
  for a given dataset.
- **INSPECT-SR and ROB-ME are not numerically validated.** They are faithful implementations
  of published *judgement* instruments (Wilkinson 2025; Cochrane Ch.13 2024+) — scaffolds with
  no numeric oracle. Their official wording is paraphrased with disclosure where download-gated.
- **6 synthesis apps have no R oracle** (§1) — disclosed, not hidden.
- **Single-maintainer; not third-party audited.** The evidence here is reproducible and
  CI-gated, but has not been independently re-run by an external body. The comparative figures
  in §4 are from the published literature, not an allmeta-run head-to-head.
- **Extraction (S3) is unsolved industry-wide**, not validated here for any tool including
  allmeta.
